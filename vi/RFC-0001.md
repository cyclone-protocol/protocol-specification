# RFC-0001 — Cyclone Là Gì

## Status

Draft

## Version

1.0.0

## Author

Ha Duy Thang

---

# 1. Một Câu

> Cyclone là một **binary wire format specification** định nghĩa dữ liệu được biểu diễn thành byte như thế nào, sao cho cùng một dữ liệu luôn cho ra **đúng một** chuỗi byte, trên mọi ngôn ngữ, mọi runtime, mọi implementation.

Cyclone định nghĩa **protocol**, không định nghĩa **implementation**.

---

# 2. Cyclone Không Phải Cái Gì

Đọc phần này trước, để không kỳ vọng sai:

```
✗ Networking Framework      ✗ RPC Framework
✗ Game Engine               ✗ Transport Protocol
✗ Serialization Library     ✗ SDK độc quyền
```

Cyclone không lo:

```
TCP / UDP / QUIC      Retransmission     Packet ordering
Matchmaking           Prediction         Replication logic
Encryption            Compression        Checksum
```

Những thứ đó xây **phía trên** Cyclone. Cyclone chỉ trả lời một câu hỏi:

```
Dữ liệu phải có hình dạng byte như thế nào.
```

---

# 3. Bài Toán Cyclone Sinh Ra Để Giải

## 3.1 Tình huống

Một hệ thống thật thường có:

```
Server        Go
Client        C# / Unity
Tool          Rust
Analytics     Python
Device        C trên vi điều khiển
```

Cả năm nơi đều phải hiểu cùng một `Player`. Và trong nhiều bài toán, chúng không chỉ cần **hiểu giống nhau** — chúng cần **sinh ra byte giống hệt nhau**.

## 3.2 Vì sao "byte giống hệt nhau" lại khó

Mỗi ngôn ngữ có một cách nghĩ riêng, và cách nghĩ đó rò rỉ vào dữ liệu:

| Nguồn khác biệt | Ví dụ |
|-----------------|-------|
| Layout bộ nhớ | Compiler sắp xếp lại field để giảm padding |
| Alignment | `struct { u8; u32; u8 }` chiếm 12 byte trong RAM, không phải 6 |
| Endianness | Big endian trên một số kiến trúc |
| String length | C#/Java đếm ký tự, Go/Rust đếm byte |
| Enum width | `int` là 4 byte ở đây, 8 byte ở kia |
| Thứ tự map/set | `HashMap` duyệt ra thứ tự khác nhau mỗi lần chạy |
| Float | Normalize `NaN`, gộp `-0.0` với `0.0` |

Mỗi khác biệt trên đều tạo ra một byte stream khác. Và điều nguy hiểm nhất:

```
Sai schema thường KHÔNG sinh lỗi.

Nó sinh dữ liệu sai một cách im lặng.
```

## 3.3 Vì sao các format phổ biến không giải được bài toán này

| Format | Vấn đề với bài toán "cùng dữ liệu → cùng byte" |
|--------|-----------------------------------------------|
| JSON | Text, thứ tự key không xác định, số thực in ra khác nhau tuỳ implementation, kích thước lớn |
| Protobuf | Tài liệu chính thức nói rõ serialization **không đảm bảo canonical**: thứ tự map, unknown field, khác biệt giữa các version đều có thể đổi byte |
| MessagePack | Một số nguyên có nhiều biểu diễn hợp lệ (`int8`, `int16`, `int32`…) → nhiều byte stream cho cùng một giá trị |
| Reflection-based (`BinaryFormatter`, `pickle`…) | Phụ thuộc runtime, phụ thuộc version, không cross-language |

Điểm chung: chúng được thiết kế để **linh hoạt**. Linh hoạt nghĩa là tồn tại nhiều cách encode hợp lệ cho cùng một dữ liệu. Với các bài toán ở §5.1, nhiều cách hợp lệ **chính là** vấn đề.

## 3.4 Bài toán, phát biểu gọn

```
Cho một lược đồ giống hệt nhau
và một giá trị logic giống hệt nhau

Model  →  Encode  →  Bytes
Bytes  →  Decode  →  Model

phải cho kết quả giống hệt nhau
trên mọi implementation tuân thủ.
```

Đó là toàn bộ những gì Cyclone đảm bảo. Không hơn.

# 4. Cyclone Giải Bằng Cách Nào

Cyclone giải bằng cách **bỏ đi mọi lựa chọn**. Ở đâu có lựa chọn, ở đó có hai implementation chọn khác nhau.

## 4.1 Năm quyết định thiết kế

### Không có metadata trên wire

```
✗ Field name    ✗ Type info    ✗ Tag ID
✗ Object header ✗ Padding      ✗ Alignment
```

Byte stream **không tự mô tả**. Nó chỉ là dữ liệu. Encoder và decoder biết trước schema.

### Vị trí là định danh duy nhất

Không có field ID. Decoder biết field nào nhờ **thứ tự**. Thứ tự đó là thứ tự **khai báo**, không phải layout bộ nhớ.

### Kích thước cố định, không varint

`UInt32` luôn 4 byte, kể cả khi giá trị là 0. Đổi lại: một giá trị → đúng một biểu diễn, không có "cách encode ngắn hơn".

### Không Optional, không default value

Mọi field bắt buộc có giá trị. Không có field vắng mặt, nên không có câu hỏi "vắng mặt thì encode thế nào".

### Schema là nguồn sự thật duy nhất, chốt tại compile-time

Không reflection lúc chạy. Mọi thứ xác định được lúc build thì phải xong lúc build.

## 4.2 Cái giá phải trả — nói thẳng

Mỗi quyết định trên đều có giá:

| Được | Mất |
|------|-----|
| Byte xác định tuyệt đối | Không có schema evolution |
| Wire nhỏ, decode nhanh | Đổi thứ tự field = breaking change |
| Không cần parse metadata | Byte stream không tự mô tả, sai schema → dữ liệu sai im lặng |
| Không có ambiguity | Không có Optional / Nullable / default |
| Không reflection | Hai bên phải deploy đồng bộ |

Cyclone **không** cố che những đánh đổi này. Nếu chúng không chấp nhận được cho bài toán của bạn, §5.3 nói rõ khi nào không nên dùng.

# 5. Vì Sao Chọn Cyclone

## 5.1 Khi tính xác định là yêu cầu, không phải điều tốt nên có

Có một nhóm bài toán mà "cùng dữ liệu → cùng byte" không phải tối ưu hoá, mà là **điều kiện đúng/sai**:

| Bài toán | Vì sao cần byte xác định |
|----------|--------------------------|
| Ký / hash payload | Chữ ký ký lên byte. Byte đổi → chữ ký sai, dù dữ liệu logic không đổi |
| Replay / lockstep | Hai máy phải chạy ra cùng một world state từ cùng một chuỗi input |
| Content-addressed / dedupe | Cùng nội dung phải cho cùng hash, nếu không cache và dedupe vô nghĩa |
| Test cross-SDK | So sánh byte là cách duy nhất kiểm chứng hai SDK thật sự tương thích |
| Audit log nhị phân | Bản ghi phải tái tạo lại được y hệt |

Với những bài toán này, một format "thường thì giống nhau" là không dùng được.

## 5.2 Khi băng thông và CPU bị siết

```
Game networking      IoT / embedded      Real-time streaming
```

Không metadata, không tag, không varint decode, không reflection, không allocation cho parser. Wire nhỏ và đường đi từ byte tới model rất ngắn.

## 5.3 Khi nào KHÔNG nên chọn Cyclone

Quan trọng ngang phần trên:

| Tình huống | Vì sao không hợp |
|-----------|------------------|
| Public API cho bên thứ ba tự tiến hoá | v1 không có schema evolution. Thêm một field là breaking change |
| Client cũ và server mới phải sống chung lâu dài | Không có unknown-field skipping, không có default |
| Cần người đọc được dữ liệu bằng mắt | Cyclone là nhị phân thuần |
| Model có nhiều field "có thể không có" | Không có Optional / Nullable trong v1 |
| Schema đổi liên tục theo tuần | Mỗi lần đổi phải deploy đồng bộ hai phía |

Nếu bạn thuộc các nhóm này, một format có tag ID và optional field sẽ phục vụ tốt hơn. Đó là lựa chọn đúng, không phải thất bại của Cyclone.

# 6. Sức Mạnh Của Cyclone

## 6.1 Determinism ở mức byte

```
Go SDK      encode Player{hp=100, name="Alice"}  →  bytes A
C# SDK      encode Player{hp=100, name="Alice"}  →  bytes A
Rust SDK    encode Player{hp=100, name="Alice"}  →  bytes A
```

Giống hệt, từng byte một. Nếu khác, đó là **bug của implementation**, không phải đặc điểm của protocol — và bug đó bắt được bằng một phép so sánh mảng byte.

Đây là thứ mở khoá toàn bộ §5.1: hash, chữ ký, replay, dedupe, conformance test.

## 6.2 Wire nhỏ

Một `Player` đầy đủ (struct lồng, string, enum, bool, array of struct):

```
Cyclone   49 byte
JSON      ~140 byte cho cùng dữ liệu
```

Gần **3 lần**. Khác biệt này không đến từ thuật toán nén, mà đến từ việc **không gửi những thứ không phải dữ liệu**: không tên field, không dấu ngoặc, không dấu phẩy, không tag.

Và nó dự đoán được: kích thước tính ra bằng phép cộng, không phụ thuộc nội dung.

## 6.3 Không reflection lúc chạy

```
Compile time                Runtime
────────────                ───────
Đọc schema                  Ghi byte
Sinh codec                  Đọc byte
Kiểm tra hợp lệ             (hết)
```

Hệ quả thực tế:

- Chạy được trên môi trường AOT — IL2CPP, Unity console, mobile, embedded.
- Không allocation cho việc phân tích type lúc chạy.
- Không tra bảng metadata trên hot path.
- Không có "lần đầu chậm" do warm-up reflection.

## 6.4 Sai thì sai lúc build

Schema không hợp lệ — enum âm, tên trùng, đệ quy vô hạn, constraint sai — bị từ chối tại thời điểm định nghĩa schema. Không hoãn tới runtime.

Lỗi rẻ nhất là lỗi không bao giờ lên production.

## 6.5 Implementation thay thế được

Specification chỉ mô tả hình dạng byte. Nó không quy định API, không quy định phải generate code, không quy định phải dùng annotation. Nên nó triển khai được bằng:

```
Compiler sinh code    Reflection    Viết tay
FPGA                  PLC           Assembly
```

Phép thử: *một người viết encoder bằng assembly trên vi điều khiển 8-bit có tuân theo được phát biểu này không?* Nếu không — phát biểu đó không thuộc Specification.

Reference Implementation **không phải** chuẩn. Specification mới là chuẩn. Thay toàn bộ implementation, wire format không đổi.

## 6.6 Model vẫn là của bạn

Cyclone không bắt bạn viết một lớp DTO song song để truyền qua mạng, không bắt kế thừa base class, không bắt implement interface.

Cyclone đọc **model có sẵn của bạn**, chỉ những field được đánh dấu là network field. Phần còn lại của class — logic, method, field nội bộ — Cyclone không nhìn tới và không quan tâm.

# 7. Cyclone Nằm Ở Đâu

```
        Application
        (game logic, RPC, replication, prediction)
              ↑
        ┌─────────────┐
        │   CYCLONE   │   Model ↔ Bytes
        └─────────────┘
              ↑
        Transport
        (TCP / UDP / QUIC / serial / file)
```

Cyclone không biết gì về tầng trên và tầng dưới. Nó chỉ đứng đúng ở chỗ dữ liệu đổi hình dạng.

# 8. Triết Lý

```
Specification First          Specification là nguồn sự thật duy nhất
Protocol over Framework      Định nghĩa byte, không định nghĩa API
User Owns the Model          Không bắt viết lại model
Compile-time over Runtime    Xác định được lúc build thì xong lúc build
Zero Runtime Reflection      Runtime chỉ đọc và ghi byte
Minimal Wire Format          Chỉ gửi dữ liệu, không gửi mô tả dữ liệu
Deterministic by Design      Một dữ liệu, đúng một chuỗi byte
Language Neutral             Không ngôn ngữ nào là ngôn ngữ chính
Implementation Independent   Không quy định parser / macro / generator
Implementation Replaceable   Reference Implementation không phải chuẩn
```

Một quy tắc quyết định duy nhất cho mọi thay đổi trong tương lai:

> Thay đổi này có vi phạm nguyên tắc nào ở trên không?
>
> Có → không thuộc Cyclone.
